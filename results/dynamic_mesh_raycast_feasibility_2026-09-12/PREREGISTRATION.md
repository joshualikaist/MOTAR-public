# 사전등록 — 움직이는 강체 메시의 광선 교차 타당성 (2026-09-12)

**결과를 보기 전에 커밋한다.** 판정 기준과 중단 규칙을 먼저 고정한다.

## 질문 — 그래픽스 문제 하나뿐이다

> **매 프레임 정적 장면 BVH를 다시 만들지 않고, 프레임마다 자세가 바뀌는 강체 메시를 광선과
> 교차시킬 수 있는가?**

검출기·연관·정책·태스크에 연결하지 않는다. 표적 탐지 로직을 개선하지 않는다.

## 왜 지금 이 질문인가 — 경계의 기록

`navrl_physical_target_params`는 `include_in_warp = False`다. 표적 메시는 정적 Warp 장면에
**들어가지 않는다.** 따라서 검출기가 URDF의 visual을 보지 않는 것은 **자산 버그가 아니라 렌더러
구조의 결과**다. 현재 증거와 일관된 서술은 이것뿐이다:

```
URDF visual 변경  →  Isaac 자산 외형 변경
그러나
표적 마스크  →  해석적 구/상자 프록시  →  URDF visual geometry는 마스크에 영향을 주지 않는다
```

이 구조는 의도적으로 보인다. 표적이 움직이는데 Warp 메시 장면은 한 번 만들어지므로, 매 스텝
BVH 재적합 비용을 피하려고 정적 기하만 넣고 움직이는 표적은 해석적으로 처리한 것이다.

## 설계

```
world frame 카메라 광선
   ↓  T_world_object 의 역변환
object-local 광선
   ↓
object-local 정적 메시 / BVH   (재구성하지 않는다)
   ↓
교차: 거리 · 법선 · face ID · hit
   ↓  T_world_object 로 되돌림
world/camera frame
```

**정적 장면 BVH와 동적 물체 BVH를 완전히 분리한다.** 하나의 `mesh_ids[env_id]`에 동적 물체를
넣지 않는다. 최종 거리는 `d = min(d_static, d_dynamic)`로 결정할 수 있는지 검증한다. 이렇게 하면
표적이 자기 자신을 가리는 공유 메시 문제를 피할 수 있는지 확인된다.

## 기하 — 일반 자산부터

UAV 표적을 쓰지 않는다. **비대칭 상자**와 **L자 형상**으로 시작한다. 비대칭이어야 회전이 투영
패턴을 실제로 바꾼다.

## 정확성 게이트 — 실행 전에 고정

| | 검사 | 통과 기준 |
|---|---|---|
| C1 | 평행이동 | 메시를 x = 0, +1, −1 m로 옮길 때 광선 거리가 **정확히** 그만큼 이동. 허용오차 **1e-5 m** |
| C2 | 회전 | 비대칭 형상을 회전하면 hit 픽셀 집합이 바뀐다. 최소 **5%**의 유효 픽셀에서 hit 여부가 달라질 것 |
| C3 | 역변환 동등성 | world-space로 변환한 메시와의 교차 대 object-local 메시 + 역변환 광선. 깊이 **1e-5 m**, 법선 **1e-4** 이내 |
| C4 | 법선 변환 | world로 되돌린 법선이 단위 길이(**1e-5**)이고, 볼록 형상에서 카메라를 향한다(`dot(n, -d) > 0`) |
| C5 | BVH 재구성 없음 | 자세만 바꿀 때 `wp.Mesh` 객체의 `id`와 정점 버퍼 포인터가 **변하지 않는다** |

**C3의 참조 구현은 CPU numpy로 따로 쓴다.** 같은 코드로 자신을 검증하지 않는다.

## 애니메이션 시퀀스

평행이동 / 회전 / 평행이동+회전 세 가지를 **100프레임** 기록한다: frame, pose, hit count,
depth SHA-256, normal SHA-256, face-ID SHA-256. 같은 seed·같은 pose에서 **두 독립 프로세스가
바이트 동일**해야 한다.

## 성능 — 정확성 게이트를 통과한 뒤에만 측정한다

세 arm을 **같은** 해상도·카메라·정적 기하·물체 자세 시퀀스·장면 수로 비교한다.

```
STATIC_ONLY
STATIC + DYNAMIC_ANALYTIC_PROXY
STATIC + DYNAMIC_LOCAL_MESH
```

기록: 기하 질의 시간, 전체 렌더 시간(각각 mean / median / P95), FPS, torch 최대 할당·예약,
프로세스 RSS, 가능하면 CUDA VRAM.

**기존 R5 숫자를 기대값으로 쓰지 않는다.** 3.09 ms·9.14 ms·R5 음영 비용은 서로 다른 fixture와
단계의 측정이며, 새 경로의 비용을 그것으로 보간하지 않는다. 통합 비용은 현재
`INTEGRATED_RENDER_COST_UNMEASURED`이고 이 실험이 그것을 측정한다.

## 규모와 자원 중단 규칙 — 결과를 보고 바꾸지 않는다

해상도 160×90, 320×180, 480×270 × 장면 수 1, 32, 128.

**8 GB 카드이므로 작은 셀부터 실행한다.** 규칙을 미리 적는다:

1. 셀은 (장면 수, 해상도) 오름차순으로 실행한다.
2. 어떤 셀이 torch 예약 **6.0 GiB**를 넘으면 그보다 큰 셀은 실행하지 않고
   `NOT_RUN_RESOURCE_LIMIT`으로 기록한다.
3. OOM이 나면 그 셀을 `OOM`으로 기록하고 같은 규칙으로 중단한다.
4. **결과를 얻으려고 행렬을 사후에 바꾸지 않는다.**

## 성능 판정 — 기준을 먼저 세운다

기준선은 이 실험이 **같은 조건에서 측정한** `STATIC_ONLY`와 `STATIC + ANALYTIC_PROXY`다.
임의의 절대 숫자를 만들지 않는다. 학습 해상도(160×90)·장면 128에서:

| 판정 | 조건 |
|---|---|
| `INTEGRATION_WORTHY` | `STATIC + DYNAMIC_LOCAL_MESH`의 전체 렌더 중앙값이 `STATIC + ANALYTIC_PROXY` 대비 **1.5배 이하**, 그리고 메모리가 중단 규칙 안 |
| `TOO_EXPENSIVE` | **3.0배 초과**, 또는 그 셀이 자원 규칙에 걸림 |
| `INCONCLUSIVE` | 그 사이(1.5–3.0배), 또는 정확성 게이트 미통과로 성능을 재지 못함 |

## 성공해도 말하지 않는 것

정확성과 성능을 모두 통과해도 주장할 수 있는 것은 **딱 이것뿐이다**:

> object-local 광선 변환으로 동적 강체 메시를 정적 BVH 재구성 없이 렌더링하는 독립 경로가
> 정확성·성능 게이트를 통과했다.

다음은 **주장하지 않는다**: 실제 검출기가 형상을 사용한다, 색 지름길이 줄었다, 인지가 좋아졌다,
연관·정책·태스크 성능이 변한다.

## 이 실험이 전제조건으로 두지 않는 것

`0.283` 대 `0.28` 기하 계약 불일치는 **이 타당성 실험의 선행조건이 아니다.** 프로토타입은 기존
기하 의미를 그대로 보존한다. 그 불일치는 `GEOMETRY_CONTRACT_DECISION_PENDING`으로 따로 기록하며
**본 검출기 통합 전에만** 결정하면 된다. 선택지 예시(A: 센서 0.283 / 접촉 0.28 유지, B: 통합 계약,
C: visual·sensor·collision을 명시적으로 분리) 중 하나를 **타당성 결과를 보기 전에 고르지 않는다.**

## 구현 위치

기존 검출기 커널을 수정하지 않는다. 독립 렌더러 모듈과 `tools/`·`tests/` 안에서만 작업한다.
공유 production 경로를 건드려야만 가능하다는 결론이 나면 **그 시점에서 멈추고 이유를 보고한다.**
