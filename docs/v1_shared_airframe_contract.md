## 역사 계약 — 2026-09-11 원문, 현재 실행 지시 아님

계획의 2번. 표적이 **밋밋한 빨간 상자**라서 색만으로 판별될 수 있다는 문제를 없앤다.

## 앞선 단계에서 측정으로 드러난 것

URDF 로더로 두 자산을 재 보니 계획서 원문("표적을 요격기 자산으로 교체")은 의도와 반대로 간다.
요격기 visual은 0.176 m로 **자기 충돌 상자(0.283 m)의 62%**이고, 보이는 픽셀의 **64.4%가 흰 구**다.
그대로 복제하면 표적이 더 작아지고 덜 드론 같아진다. 그래서 **공유 기체 외형을 새로 만들어** 쓴다.

## 이번 단계의 범위 — 표적의 visual만

**표적 URDF 하나만** 다룬다. 요격기와 방해물은 다음 단계다. 이유는 셋이다.

1. 시뮬레이터의 기하 추출은 **`collision`만 읽는다.** `asset_loader.py`의
   `.//collision/geometry/{box,sphere,cylinder}`와 `navrl_task.py`의
   `link[@name='base_link']/collision/geometry/box`뿐이다. `visual`은 읽지 않는다.
   따라서 visual만 바꾸면 **스폰·충돌·물리에 영향이 0**이다.
2. 방해물은 `test_navrl_distractors.py`(1,555줄)가 **단일 링크·단일 프리미티브**로 고정하고 있고
   시뮬레이터가 프리미티브 하나를 읽어 footprint를 계산한다. 같이 바꾸면 범위가 훨씬 커진다.
3. 요격기 visual 변경은 **카메라가 요격기를 보지 않으므로 학습에 영향이 없다.** 급하지 않다.

## 새 파일을 만든다 — 기존 파일은 건드리지 않는다

`navrl_target_drone_v3.urdf`를 새로 만들고 config가 그것을 가리키게 한다. v2는 그대로 둔다.
되돌리기가 **config 한 줄**이고, 두 파일을 나란히 비교할 수 있다. 저장소가 v1→v2에서 쓴 방식이다.

## 바뀌지 않아야 하는 것 — 테스트로 고정한다

v2와 v3에서 **완전히 동일**해야 한다.
- `<inertial>`의 mass와 inertia 전부
- `<collision>`의 geometry와 origin (상자 0.283 × 0.283 × 0.12)
- 링크 이름 `base_link`, 링크 개수 1
- `asset_loader.py`와 `navrl_task.py`의 추출 결과

## 기하 — 모든 수치의 출처를 밝힌다

새로 정하는 숫자가 **하나도 없다.** 전부 기존 소스에서 가져온다.

| 부품 | 값 | 출처 |
|---|---|---|
| 모터 위치 | (±0.0777817, ±0.0777817, 0) | `quad_navrl_ref5in_v2.urdf` joint origin |
| 팔 | 원기둥 r=0.01, L=0.11 | 같은 URDF의 `arm_motor_*` visual |
| 모터 | 원기둥 r=0.01, L=0.05 | 같은 URDF의 `motor_*` visual |
| 프로펠러 반경 | 0.0635 | `navrl_task.py`의 `PROP_RADIUS_5IN_M` |
| 몸체 | 상자 0.15 × 0.15 × 0.12 | 같은 URDF 주석의 관성 근사 상자 |

팔 길이 0.11은 모터까지의 반경 0.1099999와 일치한다. 즉 팔이 중심에서 모터까지 정확히 닿는다.
프로펠러 끝 span은 2 × (0.0777817 + 0.0635) = **0.2825634 m**로 충돌 상자 0.283 안에 들어간다.

**따라서 겉보기 최대 폭이 0.283 → 0.2826으로 0.16%만 바뀐다.** 앞서 우려했던 28% 축소가 없다.

## 색 — 지금은 화면에 닿지 않는다

`navrl_detector.render_raw_rgbd()`가 표적 픽셀을 `target_color`로 **평면 채움**하므로 URDF의 색은
현재 이미지에 **전혀 반영되지 않는다.** 그래도 부품별 중립 회색 계열을 선언해 둔다. V2에서 평면
채움을 음영으로 바꿀 때 이 값이 쓰인다. **이번 단계는 색에 대해 아무 효과도 주장하지 않는다.**

## 검증 — 측정으로 한다

1. v2와 v3의 `<inertial>`·`<collision>` XML이 동일한지 (파싱 후 비교)
2. `asset_loader.py`·`navrl_task.py` 추출 결과가 v2와 v3에서 동일한지 — **실제 함수를 호출해서**
3. 로더로 읽어 **닫힌 표면 + winding 일치 + 부호 부피 > 0** (오목할 수 있으므로 볼록 검사 아님)
4. 겉보기 크기를 **렌더해서 픽셀로 잰다.** 같은 카메라·같은 거리에서 v2와 v3의 픽셀 수를 비교한다.
   계산으로 넘겨짚지 않는다.
5. 생성기를 다시 돌리면 커밋된 파일이 **바이트 동일**하게 재생성되는지
6. 전체 테스트

## 이 단계가 말하지 않는 것

색 지름길 감소, 검출 성능, 학습 결과에 대해 아무 주장도 하지 않는다. 요격기와 방해물은 아직
바꾸지 않는다. 정책 재학습도 하지 않는다.
