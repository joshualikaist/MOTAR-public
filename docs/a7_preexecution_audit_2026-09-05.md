# A7 실행 전 감사 — 2026-09-05

대상: [A7 사전등록](prereg_2026-09-05_a7_arc_attribution.md).
새 GPU 평가 결과는 없다. 아래는 기존 결과 JSON과 CPU 계산에서 확인한 사항이며,
사전등록의 동결된 판정 규칙을 대체하지 않는다.

## 1. M2: 기존 원호 함수의 yaw=0 극한이 직선과 다르다

`arc_clearance`는 `abs(yaw_rate) < 1e-3`에서 반경을 `1e6`으로 대체하지만,
튜브 횡거리는 여전히 `sqrt(px² + (py - radius)²) - abs(radius)`로 계산한다.
float32에서 큰 수의 차를 구하면서 ±0.45 m 경계 판정이 달라진다.

CPU 재현 입력:

- `bearings = [asin(0.46 / 4)]`
- `scan = [[[4 / cos(20°)]]]` (수평 투영 후 거리 4 m)
- `command_xy = [[3.5, 0]]`, `yaw_rate = [0]`
- `max_range_m = 12`, `path_half_width_m = 0.45`

직선 clearance는 **12 m**, 원호 clearance는 **3.9734618664 m**다.
고정 난수의 128개 배치 검사에서도 최대 차이 **0.1074583307 m**가 재현됐다.
새 `A7RiskcapArc` 회귀 테스트는 이 불일치를 검사하며, 수정 전에는 실패해야 한다.

제안하는 최소 수정은 기존 `straight` 마스크에서 횡거리를 직접 `abs(py)`로 계산하는 것이다.
기존 `perp` 계산 뒤 `perp = torch.where(straight, py.abs(), perp)`를 넣는 수정안을
메모리에서만 적용했을 때 거버너 테스트 **25/25 PASS**였다. 실제 원호 함수는 수정하지 않았다.
비영 yaw 구간의 원호 계산과 정지법칙은 보존한다. 두 원호 모드가 같은 함수를 써야 하므로,
이 수정은 `dwa_arc`에도 적용된다. 따라서 새 `riskcap`의 M5 통과만으로 옛 A4 `dwa_arc`를
새 원호 모드와 동등한 구현이라고 볼 수 없다. **P1을 처음부터 동일 커밋의 4 arm으로 실행**하는
수정안이 필요하다(총 12 arm, 원안 대비 2 arm 증가). 이 예산 변경은 사용자 결정 대기다.

요청 에피소드는 2049지만 종료 배치에 따라 실제 분모가 더 크다. CI에는 각 JSON의

M5는 비율 재현 검사이며, 옛 dirty 소스의 무결성을 소급 증명하지 않는다.

## 3. P3 해석에는 밀도 외 조건도 남는다

| 조건 | A4 / P1·P2 | 기존 205-bar 스크린 / P3 |
|---|---|---|
| 기체 | `navrl_ref5in_quad` | `navrl_quad` |
| 기체 파일 | `quad_navrl_ref5in.urdf` | `quad_navrl_collide.urdf` |
| 초기 목표 거리 | 22.5–28 m | 6–28 m |
| 체크포인트 | ref5in ep1900 | ep25000 |
| 막대 수 | 70 | 205 |

따라서 `FLIP_IS_DENSITY` / `DENSITY_LIMITED`라는 사전등록 라벨을 출력하더라도 해석은
**실행 조건 사이의 전이 제한**이다. 밀도의 단독 인과효과로 서술하지 않는다.
옛 스크린과 새 P3의 brake 대조에도 소스 및 계측 차이가 있으므로 M5 재현은 필요한 확인이지만
모든 교란을 제거한 증명은 아니다.

## 4. 판정 규칙의 미정 경계

- `G_risk >= +3 pp`이고 그 CI만 0을 제외하면 `INTERACTION`과
  `ARC_HURTS_UNDER_RISKCAP`이 동시에 성립한다. 우선순위 사용자 결정 대기.
- M5의 둘째 자리 일치가 깨졌지만 차이가 0.5 pp 이하일 때 처리 방식은 원문에 없다.
  교차 루트 비교 허용 여부 사용자 결정 대기.
- P3에서 `-3 < L_line < 0`이며 CI가 0을 제외하면 두 FLIP 라벨 중 어느 것도 성립하지 않는다.
  이 경우 판정 조건 불충족으로 보고하며 임계값을 완화하지 않는다.
- `INTERACTION`은 원문의 “유의성 한쪽만 성립” 규칙 이름이다. 그 자체로 정식
  차이의 차이 상호작용 검정이 유의함을 의미하지 않는다.

## 5. 실행 상태

`riskcap_arc`의 법칙/설정/작업 분기, 평가 셸의 두 화이트리스트와 별도 riskcap 검증을 추가했다.
같은 clearance의 cap 동등성은 CPU에서 통과했다. M2 결함 수정 및 P1 예산 변경이 정해지고,
전체 CPU 검증과 코드·런처·요약기 커밋이 완료되기 전에는 A7 평가를 시작하지 않는다.
