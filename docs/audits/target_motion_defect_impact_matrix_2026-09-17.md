# Target-motion defect impact matrix — 2026-09-17

Which of the nine audited defects belong to the **historical training distribution**
(and must therefore be preserved to reproduce arm H), and which would **invalidate the
frozen-policy comparison itself**?

That distinction gates the GPU evaluation. Machine-readable counterpart:
[`target_motion_defect_impact_matrix_2026-09-17.json`](target_motion_defect_impact_matrix_2026-09-17.json),
generated by `tools/audits/build_defect_impact_matrix.py`, which **re-derives the
structural facts at build time and refuses to emit the matrix if any of them stops
being true**.

## The classification

```text
TYPE-A   historical behaviour that must be PRESERVED to reproduce arm H
TYPE-B   current evaluation bug that INVALIDATES new measurements
TYPE-C   receipt / provenance mislabelling only; physics unchanged
TYPE-D   future-design debt; does not invalidate the frozen evaluation
```

A TYPE-A defect must **not** be "fixed because it is a bug". Arm H exists to reproduce
the lineage the frozen policy actually trained in; repairing the lineage inside H would
stop H from being that reproduction.

> **A historical defect is not the same thing as an evaluation implementation bug.**

## The decisive structural fact

Everything about D1's scope follows from one property of `_advance_target`:

```text
if self._target_dynamics in ("bounded", "physical"):
    ...
    return          <-- line 8082, UNCONDITIONAL, no else branch

# everything below is reached only when dynamics == "legacy":
#   line 8205  bar push-out (pure position displacement, up to 6 rounds)
#   line 8232  bounce reflection, jitter from the GLOBAL torch RNG
#   line 8249  target_vel_w = (new_position - old_position) / dt
```

Verified by AST, not by reading indentation: the branch's last statement is a `Return`
and it has no `else`. E0, E1 and E2 all run under `bounded` dynamics, so the entire
push-out / reflection / velocity-rewrite block is **structurally unreachable** for them.

```text
E2_UNAFFECTED_BY_D1 = TRUE   (proven, not assumed)
```

## Per-defect detail

### D1 — TYPE-A · MAJOR · `preserve`

`aerial_gym/task/navrl_task/navrl_task.py:_advance_target legacy block`

**Historical families potentially affected:** every legacy/mixed target family: density curves, density x speed map, capture/crash/timeout triples trained or evaluated under legacy dynamics.  
**New evaluation affected:** H_historical only.

> H exists to reproduce the frozen policy's actual training lineage. Repairing D1 inside H would stop H from being that reproduction. Historical defect != evaluation implementation bug.

## The heading-validity threshold gates the turn-rate bound

Found while auditing E2, and it is **not** on the original defect list because it is
not a defect — it is a contract whose provenance is missing.

`limit_planar_velocity` does not apply the slew limit unconditionally:

```python
limited_heading = torch.where(
    current_speed > HEADING_VALID_SPEED_MPS, limited_heading, desired_heading
)
```

with the docstring stating it plainly: *"Below `HEADING_VALID_SPEED_MPS` there is no
heading of travel, so the first command starts in the requested direction; above that
speed the heading slew limit applies."* The threshold is **0.10 m/s**, deliberately the
frozen braking stop speed rather than a numeric epsilon, so that millimetre-per-second
PhysX residuals cannot lock the limiter onto a noise heading.

Two consequences that matter for this evaluation:

1. **The turn-rate bound is conditional.** Below 0.10 m/s a bounded target may pivot to
   any heading in one step. With `speed_min = 0.3` and cruise scales
   `{1.0, 0.5, 0.25}`, the quarter-speed candidate at the minimum episode speed is
   `0.075 m/s` — **below the threshold**. So free pivots are reachable in normal E1/E2
   operation, not only at a standstill. An audit that checks the turn bound against a
   numeric epsilon will report contract-conformant behaviour as a violation; this one
   checks against `HEADING_VALID_SPEED_MPS`.

2. **It lands exactly on the provenance gap.** The frozen checkpoint does not attest
   this key (`ASSUMED_PRE_KEY_DEFAULT`), and the source records that pre-key lineages
   ran an inline `1e-05 m/s` epsilon. Under `1e-05` the slew limit applies essentially
   always; under `0.10` it does not. The threshold therefore changes **target
   kinematics**, not merely metric semantics.

It affects `limit_planar_velocity`, which is used by the **bounded** executor — so
E0/E1/E2. Arm H uses `steer_target_step` and does not call it. The threshold is held
identical across all arms, so it cannot confound the contrast, and it is recorded as
`ASSUMED` in every result.

## E2 validity — and four ways the audit harness was wrong before the executor was

`tools/audits/audit_e2_target_validity.py` exercises `bounded_drone_target_step`
directly on CPU over `navrl_band` layouts. Final result, 12 cases (4 densities x 3
seeds), **115,200 env-steps**:

```text
obstacle penetration   0      wall violation   0
clearance violation    0      speed violation  0
acceleration violation 0      turn violation   0
teleport               0      NaN / Inf        0
global RNG draws       0      infeasible steps 0
TM-E2 TARGET VALIDITY: PASS
```

It took four corrections to get there, and **every one of them was the harness, not
the executor**. Recorded because reporting any of them as an E2 defect would have
been a serious false alarm, and because they are the failure modes any future audit
of this executor will hit:

1. **Spawns inside obstacles.** 3 of 64 initial positions started inside a bar. An
   executor cannot be blamed for a target that begins inside an obstacle. Fixed by
   rejection-sampling spawns and goals outside the clearance envelope.
2. **Float32 noise read as a teleport.** The worst displacement exceeded the bound by
   `1.8e-06` m against a `1e-6` tolerance. Replaced with a relative tolerance.
3. **The turn bound checked below the rest threshold.** `limit_planar_velocity`
   grants a free heading below `HEADING_VALID_SPEED_MPS` by contract; the harness
   used `1e-4`. The one flagged event had `|v| = 0.0199 < 0.10`, i.e.
   contract-conformant behaviour counted as a violation.
4. **The wrong lineage's geometry contract.** The harness passed
   `bars_half_extents` with a 1.0 m *surface* clearance — the **physical** target's
   contract. The bounded lineage passes `bars_half_extents = None` and
   `clearance = tm.obstacle_clearance = 0.77 m`, a **centre-to-centre** test
   (`navrl_task.py:7873`, `_target_planner_clearance`). That distinction is not
   cosmetic: 0.77 m sits just inside the `navrl_band` corridor half-width of 0.8 m,
   so the real contract fits through a legal corridor and the physical one does not.
   Auditing with the wrong one made legal corridors impassable and manufactured the
   trapped states that produced every remaining penetration.

The lesson generalises: **an audit must replay the production call contract exactly**,
or it measures its own configuration. Three of the four errors produced
plausible-looking failures that a less sceptical reading would have published as
target-generator defects.

## RNG audit

```text
target_motion.py            ZERO random draws        (regex-verified at matrix build time)
bounded executor (E0/E1/E2) consumes no RNG
legacy bounce jitter (H)    torch.rand on the GLOBAL stream, conditional on bar contacts
obstacle poses              asset_manager.reset_idx, torch.rand on the GLOBAL stream,
                            resampled PER EPISODE
no torch.Generator          anywhere in navrl_task.py
```

The consequence, stated precisely because it is easy to overstate:

- **Within an arm**, a seed fully determines the run. Determinism holds.
- **Across arms**, the streams diverge. Arm H consumes extra draws on bar contacts;
  among E0/E1/E2, waypoint resampling fires only for the waypoint pattern. Since
  obstacle poses come from the same global stream, **the same seed does not produce the
  same bar layout in different arms.**
- This is a **loss of paired matching, not a bias**: every arm still draws layouts from
  the same distribution, and the comparison is over 2048 episodes x 3 seeds.

Therefore the design must be described as **distributional matching, not paired-layout
matching**. The preregistration's analysis is unaffected because it pairs on *seed* at
the seed-mean level, never on episode-level layout. Recorded rather than repaired:
introducing a dedicated generator would change the historical RNG behaviour that arm H
exists to reproduce.

## Reset audit

Reset at `navrl_task.reset_idx`: target position, velocity and heading, CV velocity,
pattern, circle centre/angvel, `turn_sign`, waypoint, route-manager validity/cursor/
status, pursuer pose and velocity, motor state, prev-action buffer, Transformer history
buffers, tracker state and covariance, detector memory, per-episode telemetry counters.

Two documented non-resets, neither reachable under this contract:

- route-manager `waypoints` / `segment_start` / `goal` / `planned_support` survive reset,
  but every consumer is gated on `valid`, which **is** reset. Diagnostic exposure only,
  and route mode is `off` in all 48 cells.
- `_detector_noise_range_ar` (D8) and `_detector_noise_missing` are not reset; the first
  is an unintended omission, the second a documented modelling choice. Both are gated by
  knobs that default to `0.0` and are set by no cell.

The speed governor holds **no per-env state** (frozen dataclass config, pure entry
points), so there is nothing to leak.

```text
RESET CONTRACT = NO CROSS-ARM LEAKAGE under the 48-cell contract
```

## What this matrix does not do

No code is changed. No physics, action semantics, termination, reward or controller is
touched. No historical result is recomputed or overwritten. Every `fix-new-lineage`
action means exactly that: it belongs to a future clean lineage, not to a patch applied
underneath existing evidence.
